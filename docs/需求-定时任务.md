# 需求：定时任务

- 整理：2026-11-18（来自 [待办](待办.md) 第 2 项）
- 起因：2026-11-14 对比 Grok Bot 后提出，比如每天早上跑一遍测试、整理当天的资料。时间规则和「上一次没跑完就跳过」参考了 [OpenMausBot](https://github.com/milind-soni/OpenMausBot)。
- 限制：只在电脑开着、Agenda 开着时运行，不做云端。

## 一、时间

三种：

- **只跑一次**：某天几点；
- **每周几**：选星期几（可以多选）加时间，「每天」就是七天全选；
- **每隔多久**：每隔 N 分钟或 N 小时，最少 5 分钟（2026-11-19 定）。

规则：

- 上一次还没跑完，这一次就跳过，在运行记录里记「上一次还没结束，跳过」。
- **错过的时间点直接跳过**（当时电脑或 Agenda 没开），运行记录里记一笔「错过了」，不补跑。
- 跑的时候不让电脑睡眠，沿用现在的防睡眠设置。

## 二、到点做什么

两种，建定时任务时选一种：

1. **新建一个任务空间**：照着一个模板建，模板包括目标、成员、协调者、共享文件夹、权限和计划确认方式（相当于到点自动点一次「再开一个类似的任务」）。同一个定时任务建出来的空间在侧栏折叠成一组，最新的在最上面。
2. **在聊天空间发一条消息**：往指定的聊天空间发一条写好的消息，成员照常发言。

- 共享文件夹每次都用模板里的同一个（2026-11-19 定）。
- 定时建出来的任务空间不做「规划前澄清」：协调者想问的直接按默认答案开始，列进计划的假设（2026-11-19 定，见 [需求-任务空间](需求-任务空间.md)）。

权限都按目标空间的设置走。需要你处理的情况（确认计划、审查、命令审批）照常提醒，不会因为是定时的就自动放行。

## 三、在哪设置、在哪看

- 空间设置里的「定时」标签：给这个空间加、改、停用、删除定时任务。从任务空间设置时，模板默认照搬这个空间。
- 全局设置里的「定时任务」：列出所有空间的定时任务和运行记录（什么时候跑的、结果、跳到对应的空间）。界面按 [前端规划](需求-前端规划.md) 的整页布局做。

## 四、关掉窗口以后

- **设了定时任务时**，关窗口改成缩到托盘（macOS 是菜单栏），第一次这样做时提示一次。托盘菜单里有「打开 Agenda」和「退出」。
- 没设定时任务时，关窗口照旧退出。
- 全部定时任务都停用或删掉以后，恢复成关窗口就退出。

## 五、模块与接口（2026-11-19，待确认）

这一批只做调度、动作和托盘，界面（空间设置的「定时」标签、全局设置的「定时任务」分类、侧栏分组）等前端框架合进来以后再做。

| 模块 | 做什么 | 对外接口 |
| --- | --- | --- |
| `src/scheduler.mjs`（新） | 时间规则、到点触发、跳过重叠、错过记录、运行记录；存在数据目录的 `schedules.json`。不认识空间，只调传进来的动作 | `createScheduler({ file, now, setTimer, clearTimer, actions })` → `{ list(), add(def), update(id, patch), remove(id), runs(id?), start(), stop(), hasActive() }`；纯函数 `nextTime(rule, after)`。规则：`{ type: 'once', at }`、`{ type: 'weekly', days, time }`、`{ type: 'interval', minutes }`（≥5）。`now` / `setTimer` 可换成假时钟 |
| `src/app-server.mjs` | 把调度器接到空间上：动作走 hooks；加 `/api/schedules` 的增删改查和运行记录 | 传给调度器的 `actions`：`createTaskSpace(template) → spaceId`、`postMessage(spaceId, text)`、`isBusy(schedule) → bool`（上一次建的任务空间还在规划或执行、或者目标聊天空间正在发言）。有没有启用的定时任务变了就调 `hooks.scheduleActive(on)` |
| `src/space.mjs`（只动建空间和侧栏条目） | 建出来的空间记住来源 | 新建参数多 `scheduleId`；`listItem()` 带上 `scheduleId`，侧栏以后按它分组。`createTaskSpace` 建空间时传 `clarify: false`，这个参数由规划前澄清那部分接到任务上 |
| `electron/main.cjs` | 托盘 | 收到 `scheduleActive(true)` 时关窗口改成缩到托盘，第一次提示一次；托盘菜单「打开 Agenda」「退出」 |

- 模板：`{ title, goal, members, coordinatorId, workspace, access, planConfirm, reviewPlan, autoApprove, maxParallel }`，从任务空间设置时照搬这个空间。
- 运行记录每个定时任务留最近 200 条；一段时间里错过好几次，合成一条「错过了 N 次」。
- 「上一次还没跑完」指上一次建的任务空间还在规划或执行（写完总结、失败、结束都算跑完），或者聊天空间那一轮还没说完。

## 实现情况（2026-11-19，调度、动作和托盘；界面未做）

- **`src/scheduler.mjs`**：按第五节的接口实现，另外多了两处：`createScheduler` 多一个可选的 `onChange()`（列表或运行记录变了就调，宿主用它刷新托盘状态和界面）；多一个 `disable(id, reason)`（停用并记一条 `disabled` 记录，所属空间被删时用）。动作调用时多传一个参数 `schedule`：`createTaskSpace(template, schedule)`、`postMessage(spaceId, text, schedule)`，宿主靠它给建出来的空间记 `scheduleId`。
  - 定时任务：`{ id, spaceId, title, enabled, rule, action, nextAt, lastRunAt, createdAt, updatedAt }`。`spaceId` 是所属空间，发消息的动作就发到这个空间：`action` 是 `{ type: 'task', template }` 或 `{ type: 'message', text }`。`interval` 规则多一个锚点 `start`（不传就是建的时候）。
  - 运行记录 `status`：`ok`（带 `spaceId`）、`failed`（带 `error`）、`skipped`（`reason: 'busy'`）、`missed`（`count`、`from`、`to`）、`disabled`（`reason`，目前只有 `space_deleted`）。记的是代码不是文字，界面再翻译。
  - 定时器每次最多睡一分钟，醒来按墙上时钟检查，所以不受 setTimeout 2^31 毫秒的限制，睡眠唤醒或系统时间往后调了，一分钟内能发现错过（往前调不处理，等原来排好的时间）。到点时间过去不到 2 分钟照常跑（定时器晚到一点），超过就算错过。`once` 跑完、跳过或错过后自动停用。
  - `schedules.json` 读坏时另存成 `schedules.json.bad` 再从空的开始，单条读坏的跳过。
- **`src/app-server.mjs`**：`createTaskSpace` 和 `POST /api/spaces` 的任务空间走同一个函数（建好直接规划，开不了就删掉）；模板的 `goal` → 目标，`reviewPlan` → 审阅计划（`discuss`），带 `scheduleId` 和 `clarify: false`。`isBusy`：这个定时任务建过的任务空间里有还没开始规划的、或者任务没结束且在规划 / 等确认计划 / 执行 / 写总结；发消息的看聊天空间是不是在发言或整理导入。所属空间被删 → 停用并记录；启动时所属空间已经不在的也一样。定时消息只能发到聊天空间。
  - 接口：`GET /api/schedules?spaceId=`、`POST /api/schedules`、`GET|PATCH|DELETE /api/schedules/:id`、`GET /api/schedules/:id/runs`、`GET /api/schedules/runs`（全部）。定时任务变了，`/api/events` 推一条 `{ type: 'schedules' }`。
  - `startServer` 多一个测试用的 `clock: { now, setTimer, clearTimer }`。
- **`src/space.mjs`**：新建参数 `scheduleId` 存进空间数据，`listItem()` 带 `scheduleId`（没有就是 `null`）。`clarify` 只是传进去，接到任务上由规划前澄清那部分做。
- **`electron/main.cjs`**：`scheduleActive(true)` 时出托盘图标（Windows 用 `icon.ico`，macOS / Linux 用缩小的 `icon.png`），关窗口改成藏起来，第一次弹系统通知提示（记在 `ui.json` 的 `trayNotice`）。托盘菜单「打开 Agenda」「退出」，单击托盘图标也打开。全部停用后：窗口开着就去掉托盘，关窗口照旧退出；窗口还藏着（比如只跑一次的刚跑完）就先留着托盘，打开窗口后再去掉。Windows 注销 / 关机不拦。
- **测试**：`test/scheduler.test.mjs`，假时钟。三种时间、校验（含间隔下限）、跳过重叠、错过合并不补跑、睡眠唤醒、长延时分段、两种动作、失败记录、持久化重启、200 条上限；另有一条经过 app-server 和模拟 AI 的：到点发消息、发言没说完跳过、照模板建任务空间（带 `scheduleId`、同一个文件夹）、计划等确认时跳过、结束后再建、重启后还在、删所属空间停用。

验证情况：

- Windows：`npm run verify` 通过；`npm run mock` 实测：有启用的定时任务时关窗口进程留着、窗口藏起来、写下了第一次提示的标记；再打开一次 Agenda 窗口回来；停用后关窗口直接退出。托盘图标本身、托盘菜单的两项和那条系统通知没有截到图，没有亲眼确认。
- 真实电脑睡眠唤醒没有实测，只用假时钟模拟了时钟跳变。
- macOS / Linux 的托盘（菜单栏图标大小、Linux 桌面有没有托盘）没有验证。
- 界面（空间设置的「定时」标签、全局设置的「定时任务」、侧栏按 `scheduleId` 分组）还没做。

## 六、界面（第二批，2026-11-20，已完成）

按前端框架的挂载点各加一个文件，不改布局：

| 模块 | 做什么 | 用到的接口 |
| --- | --- | --- |
| `public/js/schedules.js`（新） | 空间设置的「定时」标签（slot `spaceTabs`）：加、改、停用、删除，从任务空间设置时模板照搬这个空间；全局设置的「定时任务」分类（slot `settings`）：所有定时任务和运行记录，点一条跳到对应的空间 | `/api/schedules`、SSE 的 `schedules` 事件 |

- 测试：`npm run verify`；`npm run mock` 下深浅配色各截一张图；做前端先调用 unslop。

### 实现情况（2026-11-20，界面）

- **`public/js/schedules.js`**，注册两处，都是自己调接口保存，不经过空间设置弹窗底部的「保存」：
  - 空间设置的「定时」标签（`spaceTabs`，`order: 40`）：一行一个定时任务（时间、动作摘要、下次时间、开关），点一行就地展开编辑，「添加」在下面展开空白编辑器（新建时「添加」先藏起来）。时间三选一：一次（`datetime-local`，默认明天 9:00）、每周（周一到周日七个圆钮可多选，默认全选，全选时列表里写「每天」，加时间）、每隔（数字 + 分钟 / 小时，不足 5 分钟时输入框标红、保存不可点）。动作：任务空间里只有「新建任务空间」；聊天空间里「发一条消息 / 新建任务空间」二选一。新建任务空间可以改目标和计划确认方式（等我确认 / 自动开始），其余照搬当前空间：成员（带 id）、协调者（聊天空间取第一个成员）、权限、审阅计划、自动通过、并行数；文件夹一律写成 `{ type: 'folder', path: 当前空间的文件夹 }`，托管文件夹也一样，保证每次用同一个文件夹。修改已有的定时任务只改目标和计划确认方式，模板其余字段沿用。目标框下面一行弱色小字写成员名和文件夹名。已经结束的任务空间也能加（到点再开一个类似的任务）。
  - 全局设置的「定时任务」（`settings`，`order: 30`，时钟图标）：上面是所有定时任务（所属空间 · 动作摘要 · 下次时间、开关），点一行跳到所属空间；所属空间已删除的写「已删除的空间」，行和开关都不可点。下面是「运行记录」，最近 50 条：状态小圆点（成功绿、失败红、错过黄、跳过 / 停用灰）、时间、动作摘要、结果文字（成功 / 失败（鼠标提示错误）/ 上一次还没结束，跳过 / 错过 N 次 / 所属空间已删除，已停用）。点一条跳空间：成功的跳到建出来的任务空间或发消息的聊天空间，其余跳到所属空间。都没有时只显示空状态。
  - 刷新：界面打开期间自己开一个 `/api/events`，收到 `schedules`（全局页还有 `spaces`）就重拉；标签切走（`hidden`）或界面关掉时断开。编辑器开着时只更新列表，不丢正在编辑的内容；开关切换中的状态在重拉后保留。
- **`public/js/sidebar.js`**：`scheduleId` 相同的空间折叠成一组，组的位置是组里最新那个原来的位置，只显示最新的一个，下面一行「更早的 N 个」，点开在下面列出其余的（缩进对齐文字），再点收起；展开状态不持久化，当前打开的空间在折叠部分时自动展开。**和需求的偏差**：「最新」按侧栏原来的排序（`updatedAt`）算，因为 `listItem()` 没有 `createdAt`；定时建出来的任务空间一般建得越晚动得越晚，只有你回头去动旧的那个时它会排到前面。要严格按建的时间排，需要 `listItem()` 加 `createdAt`（`space.mjs` 不在这次范围内）。
- **样式**：`public/css/schedules.css`（`index.html` 加了一行）。文字翻译加在 `public/i18n.js`。
- **测试**：`test/schedules-ui.test.mjs`，按界面发的模板格式（成员带 id、按 id 指定第二个成员当协调者、托管文件夹写成 folder）建定时任务，到点建出来的任务空间协调者和文件夹都对；只改目标和计划确认方式时模板其余字段不变。界面本身没有自动测试。

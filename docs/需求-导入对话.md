# 需求：导入外部 AI 对话

- 整理：2026-11-12（多轮问答后定稿）
- 状态：✅ 已完成（2026-11-12），测试情况见文末“实现后的测试”

## 一句话

把你在 Claude Code app、Codex、DeepSeek Harness 里聊到一半的对话导进圆桌（新建空间或已有空间都行），让其他成员（比如 Gemini）接着参与。

## 能导入的来源

| 来源 | 本机记录位置 | 导入后 |
| --- | --- | --- |
| Claude Code | `%USERPROFILE%\.claude\projects\<项目>\<会话ID>.jsonl` | 导入文字，**并且 Claude 成员接着原会话继续** |
| Codex | `%CODEX_HOME%\sessions\年\月\日\rollout-*.jsonl`，标题在 `session_index.jsonl` | 只导入文字 |
| DeepSeek Harness | `%USERPROFILE%\.dsh\sessions\<项目>\session-<ID>\session.v4.jsonl.zstd` | 只导入文字 |

## 流程

1. **入口**（两个）：
   - 已有空间里点「导入对话」；
   - 新建空间时选「从一段对话开始」，见下面“新建空间时导入”。
2. **选对话**：
   - 列表里三家的对话都有，显示标题、来源、项目文件夹、最后更新时间，可以搜索；
   - 默认只显示和当前空间共享文件夹相同的对话，可以切到“全部”。
3. **选对应成员**：从空间里同类型的成员中选一个；没有同类成员时自动加一个。
   - 如果某个 Claude 成员已经在接续一段对话，再导入另一段 Claude 对话时，自动新加一个 Claude 成员。
4. **选导入方式**：按篇幅自动选好一种（见下面“按篇幅自动选方式”），窗口里显示自动选了哪种和大概篇幅，你可以改：
   - 全部原文；
   - 从某一条开始导入原文；
   - 较早部分压成摘要 + 最近原文；
   - 写 handoff 文件 + 最近原文。
5. **导入**：完成后不自动发言，等你发话。

## 新建空间时导入

- 新建空间窗口里多一个「从一段对话开始」，先选对话（列表显示全部，可以搜索），再照常选成员、权限；
- **共享文件夹**：自动填上原对话的项目文件夹，可以改；改成别的文件夹时的处理见“Claude 接续原会话”里的“文件夹不同”；
- **成员**：自动加上原对话对应的 AI（比如原对话是 Claude Code，就自动加一个负责接续的 Claude 成员），其他成员（比如 Gemini）照常添加；
- **空间名**：默认用原对话的标题，可以改；
- 导入方式和已有空间相同（按篇幅自动选，可以改）；
- 新建时只导入一段，之后想再导入其他对话，用空间里的「导入对话」。

## 导入什么

- 你和 AI 双方说的话；
- 加上每轮操作的简短摘要，比如“读取 a.js”“修改 b.md”；
- 不导入工具的原始输出（文件内容、命令结果）。

## 聊天里怎么显示

- 折叠成一块：标题、来源、时间、条数，点开看全部；
- 一个空间可以导入多段对话（比如一段 Claude 的、一段 Codex 的），每段一块。

## 导入内容怎么给到成员

- 圆桌现在每个成员每次发言只带最近 40 条聊天记录（`src/prompts.mjs` 的 `MAX_HISTORY`）。导入的内容如果当普通消息，聊几轮就被挤出去了；
- 所以每段导入作为一块**固定背景**，附在每个成员的每次发言里，不占这 40 条的名额；
- 正因为每次都附带，这块背景必须控制篇幅，见下面“按篇幅自动选方式”；
- 接续原会话的 Claude 自己记得全部内容，不需要这块背景。

## Claude 接续原会话

- 先把原会话复制一份，再接着复制出来的这份往下聊，app 里原来那段不受影响；
- 接续的 Claude 成员记得原会话里读过的文件、做过的操作；之后每次发言，只补给它圆桌里新出现的消息；
- **文件夹不同**：空间的共享文件夹和原对话的项目文件夹不同时，提醒你“原对话里的文件路径可能对不上”，你确认后照样接续；接续后的第一次发言里告诉 Claude 原来的文件夹和现在的共享文件夹分别是哪里，让它按新文件夹找文件。新建空间时默认就用原项目文件夹，一般不会遇到。
- **圆桌的规则**：接续时用 `--system-prompt-snapshot off` 传圆桌的系统提示，替换掉原会话里 app 的系统提示（已试跑确认，见“验证结果”）。

## 按篇幅自动选方式

按导入内容的篇幅（对话 + 操作摘要）自动选：

| 篇幅 | 方式 |
| --- | --- |
| 短（约 1.5 万字以内） | 全部原文 |
| 中（约 1.5–6 万字） | 较早部分压成摘要，最近约 1.5 万字保留原文 |
| 长（6 万字以上） | 写 handoff 文件，最近约 1 万字保留原文；较早部分不进聊天 |

- 摘要和 handoff 不同时写：中等用摘要，很长用 handoff；
- 导入窗口里可以手动改成别的方式（比如短对话也想要 handoff）；
- 字数门槛先用上面的默认值，以后可以放进设置里调。

## 摘要和 handoff

- **谁来写**：来源是 Claude Code 时，由接续原会话的 Claude 写；来源是 Codex / DeepSeek Harness 时，由你在导入时指定的成员读导入的文字来写。
- **摘要**：放在折叠块里，替换掉被压缩的较早部分。
- **handoff**：只在共享文件夹里存一份 `.md` 文件，内容包括讨论到哪、定了什么、还有什么没解决、下一步、涉及哪些文件。聊天里只放一句提示，告诉大家文件在哪。它会出现在改动记录里，大家都能改。

## 补导新增部分

- 圆桌记住每段导入最后导到哪一条；
- 你在原 app 里又聊了以后，折叠块上显示“有 N 条新内容”，点一下只补导之后的部分（同样带操作摘要）；
- 接续中的 Claude 成员会把补导的内容当作新消息看到；
- 补导后如果整块超过了当前方式的门槛（比如原来是“全部原文”，现在超过 1.5 万字），提示你“已经变长，要不要重新压缩”，不自动重写。

## 验证结果（2026-11-12）

### ✅ DeepSeek Harness 的 zstd 记录能直接解压

圆桌装的 Electron 45.3.0 自带 Node 24.22，`zlib.zstdDecompressSync` 可用，已经用一段真实记录试过，不需要另加组件。

注意：记录是一段段压缩后接起来的（多个 zstd frame）。电脑上单独装的 Node 24.18 只能解出第一段，Electron 里的 Node 24.22 能全部解出。所以测试读取代码时要用 Electron 跑（`ELECTRON_RUN_AS_NODE=1`）。

### ✅ 三家的记录格式都能读出需要的内容

| | Claude Code | Codex | DeepSeek Harness |
| --- | --- | --- | --- |
| 你说的话 | `type:"user"` 且内容是文字（工具结果也是 `user`，要排除） | `event_msg` → `item_completed` → `UserMessage`（只有真正的用户消息，不含系统注入的环境信息） | `user/message` |
| AI 说的话 | `assistant` 里的 `text` 块（跳过 `thinking`） | `AgentMessage`，分“过程说明”和“最终回答”两种，都要 | `assistant/message` 里的 `text` 块（跳过 `reasoning`） |
| 操作摘要 | `tool_use`：Read / Edit / Write / Bash 等，有文件路径 | `FileChange`（文件路径 + 新增/修改/删除）、`CommandExecution`（命令）、`Extension`（联网搜索） | `tool/call`：read / write / edit 等，有文件路径 |
| 项目文件夹 | 每条记录的 `cwd` | `session_meta` 的 `cwd` | `session` 的 `cwd` |
| 标题 | `custom-title`（取最后一条） | `session_index.jsonl` 的 `thread_name` | `session/title`（取最后一条，后面会被 AI 生成的标题替换） |

读取时要注意的地方：

- **Claude 记录是树状的**：倒回重来、编辑消息会产生分支，要从最后一条沿着 `parentUuid` 往回找，只取当前这条线；被压缩过的会话里有压缩摘要，要识别出来；
- **Codex 的工具调用是代码**（它用 JS 调工具），直接读调用本身看不出做了什么，所以操作摘要要用 `item_completed` 里整理好的 `FileChange` / `CommandExecution`；
- **要排除圆桌自己产生的记录**：圆桌的 DeepSeek 成员会在 `.dsh/sessions` 里留下会话（项目文件夹在 `data/spaces/…` 下），以后接续的 Claude 成员也会在 `.claude/projects` 里留下复制出来的会话，导入列表里不显示这些；
- 三家都是各软件的内部格式，没有公开说明，软件升级后可能变，读不出来时要明确提示是哪一家、哪段会话。

### ✅ Claude 复制会话后接续（已试跑）

在临时文件夹里建了一段测试会话（让它记住暗号“菠萝”，系统提示要求每次以【原会话】开头），用本机 Claude 命令行 2.1.321 + Haiku 试跑：

| 试验 | 结果 |
| --- | --- |
| `--resume <原ID> --fork-session` | ✅ 得到新会话 ID，记得暗号；原会话文件前后完全一样（校验值不变） |
| 之后用新 ID `--resume`（不再复制） | ✅ 接在同一个会话上，ID 不变，记得前面的内容 |
| 复制时传新的 `--append-system-prompt`（默认设置） | ❌ **新规则不生效**，回答仍以【原会话】开头 |
| 复制时加 `--system-prompt-snapshot off` + 新规则 | ✅ 新规则生效（以【圆桌】开头），原来的系统提示被换掉 |
| 默认设置，把规则写进消息里 | ✅ 也生效 |
| 在**别的文件夹**里接续 | ✅ **也能接上**，复制出来的会话存到新文件夹名下，工作目录是新文件夹 |

结论：

- **圆桌的规则用 `--system-prompt-snapshot off` 传**，每次发言都带上，成员或权限变了也能跟着变。原会话里 app 的系统提示会被换成圆桌的，这正是想要的；
- 接续的成员不能再用 `--no-session-persistence`，否则下一次接不上；
- 调用时要把标准输入关掉（不然命令行会等 3 秒再继续）；
- **“文件夹必须相同”这个前提不成立**：已改成文件夹不同时提醒后照样接续（2026-11-12 你定的）。

### ⏳ 要你在 app 里看一眼

复制出来的会话会不会出现在 Claude app 的历史列表里：测试会话的内容是“请记住暗号：菠萝”，一共复制出 4 段。

## 实现后的测试（2026-11-12）

- **读取真实记录**：本机 Claude Code 127 段、Codex 17 段、DeepSeek Harness 18 段都能读出（系统临时文件夹和圆桌自己数据目录里的会话不列出）。压缩过的长会话不重复、不漏；已排除后台任务通知、运行环境说明、技能目录这类不是你打的字的记录。
- **演示模式全流程**：新建空间时导入、已有空间导入、自动选方式（短的全部原文 / 很长的写交接文档）、整理时聊天暂停、第二段 Claude 对话自动新加成员、从某一条开始、重新整理，以及每个成员收到的背景内容，都已检查。
- **真实 Claude（Haiku）接续**：导入一段测试会话后，Claude 记得原对话内容，按圆桌的规则发言（知道自己在哪个空间、有哪些参与者、只有读权限），原会话的旧系统提示不再生效；第一次发言复制出新会话，之后接在同一个会话上；原会话文件前后完全一样；复制出来的会话不会出现在导入列表里。
- **界面**：选择对话、导入选项、折叠块、交接文档链接都在演示模式下看过。

没测到的：

- 用真实 AI 写摘要 / 交接文档（演示模式下流程是通的）；
- 用 Gemini 等 API 成员写摘要（需要 API key）；
- 真实的补导（要在原软件里接着聊后再补导）；
- 复制出来的会话会不会出现在 Claude app 的历史列表里（要你在 app 里看一眼）。

## 一句话

一个 Windows 桌面应用：你和多个 AI（Claude Code、Codex、DeepSeek、Gemini……）在同一个空间里自由交流，并围绕同一个文件夹一起干活。

## 设计上的决定

- **改动记录**：每个 AI 发言前后各扫描一次共享文件夹，比对出它改了哪些文件。所以无论 AI 用什么方式改文件，都能记下来、都能撤销。
- **撤销保护**：撤销前先检查文件在那次改动之后有没有被别人再改过；改过就先提醒你。
- **API 型 AI 改文件**：Gemini 这类 API 没有文件工具。软件把共享文件内容放进提示词，AI 按约定格式给出新内容，由软件写入。
- **大文件夹**：只跟踪 1MB 以下的文本文件，最多 3000 个；会跳过 `.git`、`node_modules` 等目录。
- **DeepSeek Harness 续接会话**：每个成员复用同一个会话，避免在 DeepSeek Harness 里每次发言都留下一个新会话。
- **任务协作参考 orca 的地方**：
  - 数据结构：一次任务 → 子任务依赖图 → 每次派活单独记录；
  - 工作者说明：只做自己的子任务、三句话报告、明确写成功 / 失败 / 需要确认，失败不许粉饰；
  - 需要人决定时任务被挂起，回答后带着答案重新派工；
  - 改同一批文件的任务要放进不同副本，或者设依赖；
  - 用 `git worktree add --no-track -b` 建副本。
- **和 orca 不同的地方**：
  - orca 的工作者是常驻的终端会话，靠命令行工具互发消息；这里的每个 AI 都在后台一次性运行，做完就结束，所以“报告”就是它最后的回复，由软件解析；
  - 提交由软件代做（AI 不需要碰 git）；
  - 子任务通过后先合进一条集成分支，最后由你一键合并到自己的分支。
- **Codex 的权限**：Codex 运行命令前会先放进它自己的沙箱，“可改文件”档下它仍可能运行命令，但只能写共享文件夹。

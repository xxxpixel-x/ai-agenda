# 需求：角色卡、团队、资源库与集市

- 整理：2026-11-18
- 起因：想让用户不用自己琢磨怎么配成员。挑好「前端工程师」「后端工程师」这样的角色，配好角色说明、skill、MCP，一键加进空间。参考了 [OpenMausBot](https://github.com/milind-soni/OpenMausBot) 的团队导出、Claude Code 的插件市场、[skills CLI](https://www.mintlify.com/vercel-labs/skills/guides/installation-methods) 的安装方式和 [MCP 官方注册表](https://modelcontextprotocol.io/registry/about)。
- 第一版：skill 和 MCP 支持 Claude Code、Codex 和内嵌的 pi（见 [需求-模型来源](需求-模型来源.md)，在角色卡之前做）；其他 AI 能用角色卡，但卡上的 skill 和 MCP 不生效，成员标签上提示一句。以后一定扩展到所有 AI。

## 一、和现在的成员、协调者是什么关系

- 现在一个成员有 5 项：用哪个 AI、名字、型号、思考档位、设定。
- **角色卡管专长，协调者管职位**，两件事不冲突：协调者照旧在每个空间里单独指定。同一张「前端工程师」卡，在这个空间可以当协调者，在另一个空间当工作者。
- 角色卡在聊天空间和任务空间都能用。

## 二、角色卡

一张卡包括：

| 内容 | 说明 |
| --- | --- |
| 名字 | 例如「前端工程师」，加成员时作为默认名字 |
| 角色说明 | 一份 Markdown，写这个角色负责什么、怎么做事。内置卡写中英两版 |
| 建议用的 AI | 只写哪一家，例如 Claude Code，**不写型号** |
| 推荐的 skill | 名字和来源 |
| 推荐的 MCP | 名字和来源 |

### 型号谁来填

- 卡上不放型号：用户的账号能用哪些型号谁也说不准。
- 加成员时：本机有「建议用的 AI」就用它，型号用它的默认型号；没有就换成你已连接的第一个 AI。
- 每张卡可以设「我的默认」（AI、型号、思考档位），设了以后每次自动带出来。

### 角色说明

- 每张卡在 Agenda 数据目录的 `roles/` 下，中英两版分两个文件，例如 `前端工程师.zh.md`、`前端工程师.en.md`。
- **只用当前界面语言那一版**：只显示这一版，也只把这一版发给 AI，另一版不进上下文。
- 从卡添加成员时，整份说明作为这个成员的设定。设定现在最多 2000 字，要放宽。
- 改内置卡等于另存一份你的版本，可以「恢复默认」；以后 Agenda 升级更新内置卡，不覆盖你改过的。你改过的说明只有一种语言。
- **切换界面语言后**：成员记得自己来自哪张卡。没改过说明的跟着换语言；改过的保持原样。说明一换，这个 AI 要重开会话，所以正在进行的任务空间等任务结束再换。

### 内置角色

前端工程师、后端工程师、测试、产品、审稿人、编辑、资料员。每张都配好角色说明（中英）、建议用的 AI、推荐的 skill 和 MCP。

### 成员和卡的关系

- 成员是从卡**复制**出来的：在空间里改成员不影响卡，改了卡也不影响已经建好的空间。
- 成员上可以点「存为角色卡」，把改好的版本留下来。
- 已有限制照旧：任务进行中不能换成员，只能换型号。改设定会让这个 AI 重开会话，界面上提示一句。

## 三、团队

- 一个团队 = 几张角色卡 + 谁当协调者。例如「网页开发组 = 前端 + 后端 + 测试，前端兼协调者」。
- 新建空间时可以选一个团队，一次带出全部成员（任务空间同时带出协调者），之后还能逐个改。
- 内置几个常用团队，也可以把当前空间的成员「存为团队」。

## 四、skill 和 MCP

### 装在哪

- **skill**：装进跨 AI 的通用目录 `~/.agents/skills`，只存一份，再链接进各 AI 自己的目录（例如 `~/.claude/skills`）。Codex 本来就读 `~/.agents/skills`，不用链接。
  - Windows 上文件夹用 junction（不需要管理员）；链接不了就复制一份。
- **MCP**：配置放在 Agenda 自己的名单里，只交给挂了它的成员，不写进 Claude Code / Codex 的全局配置（写进去会让 Agenda 外的每个会话都多加载一份工具定义）。

### 认出本机已经装的

- 扫描 `~/.agents/skills`、`~/.claude/skills`、Claude Code 的插件和 MCP 配置、`~/.codex/config.toml` 等。认出来的直接用，不再装第二份。
- 资源库里把「本机已有」和「在 Agenda 里装的」放在一起显示。只有在 Agenda 里装的才能在 Agenda 里删；本机原有的只能停用。

### 挂到成员上

- 低三档权限现在会关掉你账号里所有的 skill 和 MCP。改成：**只打开这个成员挂了的那几个**，其余照样关。
- 卡上推荐的没装时，加成员时提示「这张卡推荐的 2 个 skill 还没装」，可以一键安装或跳过。跳过也能照常用，只是少了这些工具。
- 要密钥的 MCP（例如 GitHub MCP 要 token）安装时填，存在本机，系统支持时加密，和现在 API key 的存法一样。

### 和空间权限冲突时

- 集市里每个 MCP 标「只读」或「会改东西」。
- 新建空间、往已有空间加角色卡成员、改空间权限这三个时候检查。会改东西的 MCP 遇上「只读」或「可改文件」档，弹窗让你选：
  - 把空间权限提到需要的那一档（提醒：这对全体成员生效）；
  - 这个成员先不挂这个 MCP；
  - 取消。
- skill 只是说明加脚本，脚本运行本来就受「可运行命令」这一档管，所以 skill 每一档都能开。

## 五、资源库与集市

- 侧栏单独一个「资源库」入口，里面有：角色卡、团队、skill 与 MCP、集市。界面按 [前端规划](需求-前端规划.md) 的整页布局做。
- **集市的内容**：
  1. **Agenda 的精选清单**：放在 Agenda 的 GitHub 仓库里，一个 JSON 文件。每条写名字、中英简介、来源链接、安装方式、支持哪些 AI；MCP 再标「只读 / 会改东西」。清单里也放角色卡和团队。别人提 PR 就能被收录。联网时拉最新的，断网时用打包进安装包的那份。
  2. **搜索更多**：MCP 直接查官方注册表；skill 可以填 GitHub 的 `owner/repo` 安装。
- 以后可以加「添加别人的清单地址」（像 Claude Code 那样有多个市场），第一版不做。
- **分享**：角色卡和团队可以导出成一个 Markdown 文件，也能导入。导出时不带聊天记录、密钥和权限；导入时先给你看一遍要建哪些东西，确认后再建。

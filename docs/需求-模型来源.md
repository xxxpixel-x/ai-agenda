# 需求：模型来源（Claude Code 配别家模型、内嵌 pi）

- 整理：2026-11-19
- 状态：第二批已完成（2026-11-20）：内嵌 pi、Claude Code 配别家模型都已接好，用模拟模型测过；真实模型跑通等有 key。实测结果和实现情况见第五节末尾
- 起因：对比 [yetone/magpie](https://github.com/yetone/magpie) 和 [OpenMausBot](https://github.com/milind-soni/OpenMausBot) 后决定把 **AI 软件（壳）** 和 **背后的模型（脑子）** 分开选。现在 DeepSeek、Kimi、智谱这些只能当 API 成员：每次发言只请求一次，Agenda 把共享文件塞进提示词，模型回复整份文件，再由 Agenda 写入。它不能运行命令、不能自己翻代码、不能改完自己验证，也用不了 skill 和 MCP。
- 目标：便宜的、国内的模型也能当「能动手的成员」，而且没有 Claude Code、没有国外账号也能用。
- 排在 [角色卡](需求-角色卡.md) 之前做，这样角色卡的「建议用的 AI」、skill 和 MCP 能直接覆盖 pi 成员。
- 这次不做：自己做模型网关、多账号自动切换、成员的「备用」、显示接口余额、隐私遮盖。

## 一、整体

| 壳 | 谁用 | 要装什么 |
| --- | --- | --- |
| Claude Code 配你的 Claude 账号 | 现在就有 | Claude Code |
| **Claude Code 配别家模型** | 装了 Claude Code、想省额度或没有 Claude 账号的 | Claude Code |
| **内嵌 pi** | 所有 API 模型，取代现在的 API 成员 | 不用装，打包在 Agenda 里 |
| Codex、Gemini CLI、DeepSeek Harness | 照旧 | 各自的软件 |
| ACP 接入 | 想接其他命令行 AI 的，见 [需求-ACP接入](需求-ACP接入.md) | 各自的软件 |

Codex 配别家模型先不做：国内这几家的接口大多不支持 OpenAI 的 Responses 格式。

## 二、Claude Code 配别家模型

- 设置的「AI 连接」里，每个 API 接口多一项「也给 Claude Code 用」，需要填 Anthropic 兼容地址。DeepSeek、Kimi、智谱的预设里填好。接口必须支持流式输出和工具调用。
- 加成员时，选 Claude Code 后再选「模型来源」：你的 Claude 账号（默认），或者某个接口。成员标签显示成「Claude Code · Kimi」。
- **每个接口用一个独立的配置目录**（参考 OpenMausBot），启动时给这个成员单独设接口地址、key 和型号，不动你本机 Claude Code 的设置，也不影响其他成员。
- 不用登录 Claude 账号。

## 三、内嵌 pi

[pi](https://pi.dev) 是 MIT 协议的开源编程 agent，拆成几个 npm 包。Agenda 把它当依赖打包进去，在自己的 Node 里直接调用，用户什么都不用装。

### 取代 API 成员

- 现有的 OpenAI 兼容接口和 Gemini API 成员**全部改走 pi**，不再保留一问一答。设置里填的接口地址、key、型号照旧，升级后自动换过去。
- 文件块协议（`<<<文件：…>>>`）和把共享文件塞进提示词的做法一起去掉。

### 工具按权限档位开关

| 空间权限 | 给 pi 的工具 |
| --- | --- |
| 只读 | 读文件、搜索、查找、列目录 |
| 可改文件 | 再加写文件、改几行 |
| 可运行命令 | 再加运行命令，每条先弹审批卡片（和 Claude Code、Codex 的卡片一样：允许、一直允许某程序、拒绝，都能附一句话） |
| 全部权限 | 全部，都不问 |

- 用 pi 的「工具调用前」钩子拦截：不在这一档的工具直接拒绝，要问的弹卡片，等你点了再放行。
- 前三档只能动共享文件夹里的文件，路径越界直接拒绝。
- 改动照常记进改动记录，写明是哪个成员改的。

### 其他

- **配置隔离**：用 `PI_CODING_AGENT_DIR` 指向 Agenda 自己的目录，不读也不改用户本机的 pi 配置。
- **skill**：pi 本来就读 `~/.agents/skills`；Agenda 每次启动时只给这个成员指定挂了的那几个，其余关掉。
- **MCP**：打包 MCP 扩展（`pi-mcp-adapter`，或者新版 pi 内置的 MCP），每个成员只写入它挂了的 MCP。
- 看图、思考档位、会话续接都接上。
- 锁定 pi 的版本，升级时跑一遍测试再发新版。

## 四、上下文和用量

- pi 和 Claude Code 配别家模型的成员，上下文和 token 用量按 [需求-上下文与额度](需求-上下文与额度.md) 显示：只显示 token 数，不算钱，不显示余额。

## 要先实测

1. pi 在 Windows 上能不能运行命令（它的运行命令工具依赖 bash）。不行的话怎么办，要你定。
2. 打包 pi 以后安装包大多少。
3. DeepSeek、Kimi 在 pi 上和在 Claude Code 上用工具稳不稳。
4. Claude Code 用独立配置目录配别家接口时，能不能完全不登录 Claude 账号。
5. 兼容性：用户自己用 magpie 之类的工具改了 Claude Code 的接口地址时，Agenda 在低三档权限用 `--safe-mode` 启动 Claude Code，还会不会走用户设的接口地址。

### 实测结果（2026-11-20，Windows 11，Node 24.18）

- **pi 的包**：pi 已经从 `@mariozechner/pi-coding-agent`（停在 0.73.1）搬到 **`@earendil-works/pi-coding-agent`**，当时最新稳定版 **1.5.2**（2026-11-10），MIT。依赖 `@earendil-works/pi-ai`（模型接口）、`pi-agent-core`、`pi-tui`、`pi-mcp`、`pi-codemode`。要求 Node ≥ 22.19；Electron 45.3 自带 Node 24.22，可以直接用。
- **SDK**：`createAgentSession({ cwd, agentDir, model, thinkingLevel, modelRuntime, resourceLoader, tools, sessionManager, settingsManager })` 在 Agenda 自己的 Node 里直接跑，用 pi-ai 自带的 faux provider（模拟模型）跑通了读文件、写文件、运行命令、用量。
- **「工具调用前」钩子**：内联扩展里 `pi.on('tool_call', …)` 返回 `{ block: true, reason }` 就拒绝，可以 `await`（等审批卡片）；`tool_result` 能改工具结果。MCP 工具、嵌套调用也走这两个钩子。
- **配置隔离**：`agentDir` 参数（等同 `PI_CODING_AGENT_DIR`）+ `SettingsManager.inMemory` + 资源加载器的 `no*` 开关，不读 `~/.pi`、`~/.agents`。
- **skill、MCP**：资源加载器能只给指定的 skill；新版 pi **内置 MCP**（`createMcpExtension`，SDK 默认不加载，要自己加），不用再打包 `pi-mcp-adapter`。
- **第 1 条（Windows 上运行命令）**：pi 的 `bash` 工具按 settings 的 `shellPath` → `%ProgramFiles%\Git\bin\bash.exe` → `%ProgramFiles(x86)%\Git\bin\bash.exe` → PATH 上的 `bash.exe` 找 bash。本机 Git 装在 `F:\Git`，从 PowerShell 启动（不带 Git Bash 的 PATH）时报 `No bash shell found`。所以 Agenda 自己找：除了上面两个位置，再从 PATH 上的 `git.exe` 推出 Git 根目录下的 `bin\bash.exe`，排除 System32 / WindowsApps 下 WSL 的 `bash.exe`；找到就把路径交给 pi，找不到就换成 pi 的 `powershell` 工具（优先 pwsh，其次 Windows PowerShell，`-NoProfile -NonInteractive -ExecutionPolicy Bypass`），两种都实测能运行命令。
- **第 2 条（安装包大多少）**：pi 带进来的依赖 111 MB（实际字节）、约 1.55 万个文件，大头是 pi-ai 里各家接口的 SDK（openai 24 MB、@anthropic-ai 13 MB、@google 11 MB、AWS 约 10 MB）。用 xz -6 压缩约 14 MB，估计 NSIS 安装包大 14 MB 左右，装好后多约 110 MB。**没有真的用 electron-builder 打包量**，是估算。
- **第 5 条（`--safe-mode` 还走不走你自己设的接口地址）**：Claude Code 2.1.326，用临时的 `CLAUDE_CONFIG_DIR`，在它的 `settings.json` 的 `env` 里写一个本地假接口地址和假 token（模拟 magpie 这类工具改的设置），加不加 `--safe-mode` 请求都发到了这个假地址。也就是说用「你的 Claude 账号」的成员会跟着你自己设的接口走，`--safe-mode` 不影响。
- **第 4 条的一半**：独立的 `CLAUDE_CONFIG_DIR`（空目录）+ `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN` + `ANTHROPIC_MODEL`，连本地假接口能正常回答，不需要登录 Claude 账号；请求带的是 `Authorization: Bearer <token>`，型号是填的那个。stderr 会多一行 `unrecognized_model` 提示，不影响。真实的 DeepSeek / Kimi 要等有 key。
- **各家 Anthropic 兼容地址**（官方文档，2026-11-20 读）：DeepSeek `https://api.deepseek.com/anthropic`、Kimi `https://api.moonshot.cn/anthropic`、智谱 `https://open.bigmodel.cn/api/anthropic`，都用 `ANTHROPIC_AUTH_TOKEN`。Kimi 文档提醒残留的 `ANTHROPIC_API_KEY` 会冲突、缺 haiku / 子代理型号会让后台任务失败；智谱另外建议 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`、`API_TIMEOUT_MS=3000000`。型号名各家文档自己都不太一致（Kimi 的 Claude Code 指南写 `kimi-k3[1m]`，快速入门写 `kimi-k3.1-pro`；智谱的 Claude Code 页写 `glm-5.2[1m]`，型号总览说旗舰是 `glm-5.3`），预设先填快速入门里的默认型号，等有 key 再确认。

### 实现情况（2026-11-20，第二批）

pi 引擎和 Claude Code 配别家模型都已接好，用模拟模型测过，`npm run verify` 通过（155 个测试；新增 `test/pi-engine.test.mjs` 16 个、`test/model-source.test.mjs` 5 个）。**真实模型（DeepSeek、Kimi、智谱）的跑通要等有 key**；现有的 Gemini API、OpenAI 兼容成员和文件块协议照旧没动。只在 Windows 上做和验证。

- **接口和第五节一致**，多出和不同的地方：
  - 注册表（`index.mjs`）：`meta.sources` 的引擎在 `list()` 里多带 `sourceChoices`（`[{ id, name, model }]`，不带 key）；`runTurn` 收成员的 `source`（接口 id），换成引擎参数：Claude Code 是 `source`（接口）+ `configDir`，pi 是 `conn`（接口）+ `agentDir`。选的接口删了、或者不再给 Claude Code 用时直接报错，**不会悄悄换回你自己的账号**。meta 多一个 `sourceRequired`（pi 没有「自己的账号」这一项，不选就用第一个接口），Claude Code 多一个 `accountLabel`。`kind` 多一种 `'embedded'`（不是命令行，设置里不显示「程序位置」；也不是 API 型，不走文件块）。
  - `settings.mjs` 多 `settings.dir`（数据目录）；接口多 `anthropicUrl`、`claudeCode`，整表替换时没传这两项就保留原值（界面只改一个接口时不会冲掉别的）。
  - `members.mjs`：成员多 `source`，只对 `meta.sources` 的引擎保留；接口不存在或不在可选范围内报错；`engineLabel` 写成「Claude Code · Kimi」，其他 AI 在提示词里看到的也是这个名字。
  - **范围外改了一行**：`src/turn-runner.mjs` 调用引擎时多传 `source: member.source`（不改的话引擎拿不到成员选的接口），顶部注释里成员的字段说明补上了 `source`；统筹已同意。
- **pi**（`src/engines/pi.mjs`，`pi/tools.mjs` 管工具和权限，`pi/sdk.mjs` 管创建会话）：
  - 依赖锁定 `@earendil-works/pi-coding-agent@1.5.2`、`@earendil-works/pi-ai@1.5.2`（精确版本），`package.json` 的 Node 要求改成 ≥ 22.19。
  - 四档权限照第三节的表开关工具，`tool_call` 钩子再兜一层；前三档读写类工具的路径先按 pi 自己的规则展开，再查是否在共享文件夹里（含符号链接、目录联接），越界拒绝；`可运行命令` 档有 `onApproval` 时每条命令（和 MCP 工具调用）先等审批卡片，拒绝和附言的说法和 Claude Code 一样；全部权限不问不查。
  - 改动记录不用额外做：pi 直接改共享文件夹里的文件，发言结束时照常记在这个成员名下（有测试）。
  - 配置隔离：会话、凭据都放在 `<数据目录>/pi`；设置用内存里的，不发现扩展、skill、提示模板、AGENTS.md；`PI_OFFLINE`、`PI_SKIP_VERSION_CHECK`、`PI_TELEMETRY=0`。测试在子进程里把家目录换成放了「毒」配置的临时目录，确认都没读到。
  - key 用 `setRuntimeApiKey` 传，不写进 pi 的接口配置（那里 `$名字` 会当环境变量、`!命令` 会被执行）。
  - 系统提示：保留 pi 自己的工具说明，Agenda 的规则追加在后面。看图（接口不支持时回退并记住）、思考档位、会话续接（返回 `sessionId`，找不到时 `resumeFailed`）、用量（token 数和上下文长度，不报窗口大小，`meta.usage.context` 为 false）都接上。请求失败时 pi 自己重试 2 次（只重试限流、5xx、网络错误）。
  - `runTurn` 收 `skills`（skill 目录数组，只加载这几个）和 `mcp`（`mcp.json` 的 `mcpServers` 格式，只连这几个，工具直接给模型），用测试里手写的 stdio MCP 服务器测通；MCP 只在可运行命令、全部权限两档开放。
  - 用了 pi 没有公开导出的几处内部文件（路径解析、会话目录、MCP 凭据存储）和一个内部方法（跳过扫描 `~/.agents`），版本锁定且有测试兜着；**升级 pi 时要先跑一遍测试**。
- **Claude Code 配别家模型**（`claude-code.mjs`）：每个接口一个配置目录 `<数据目录>/claude-code/<接口 id>`，启动时设 `CLAUDE_CONFIG_DIR`、`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`、各档型号（含 haiku、子代理，都指向同一个型号）、`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`、`API_TIMEOUT_MS`；你本机环境里的 `ANTHROPIC_*`、`CLAUDE_CODE_USE_*`、`CLAUDE_CODE_OAUTH*` 一律清空。型号走环境变量不传 `--model`；别家型号的上下文窗口 Claude Code 只能猜，不显示。用真的 Claude Code 2.1.326 连本地假接口验证过：本机留着 `ANTHROPIC_API_KEY` 和另一个 `ANTHROPIC_BASE_URL` 时，请求仍然只发到成员选的接口、只带它自己的 token。
- **界面**：
  - 设置「AI 连接」：每个 API 接口多一个「也给 Claude Code 用」勾选，勾上才露出「Anthropic 兼容地址」。DeepSeek、Kimi、智谱的预设填好了 Anthropic 兼容地址和官方文档里的默认型号（`deepseek-flash`、`kimi-k3.1-pro`、`glm-5.3`），预设默认不勾。
  - 成员：**没有另加一个「模型来源」下拉，而是合进原来的 AI 下拉**，选项是「Claude Code」「Claude Code · Kimi」「Pi · DeepSeek」…（只看 `meta.sources` 和 `sourceChoices`）。这样成员行不用多一列、不用改样式表；选了接口的，型号框提示换成接口的默认型号，也不再提示「还没有登录」。
  - 成员标签（顶栏成员、成员卡片）显示「Claude Code · Kimi」（`public/js/chat.js` 改了两处）。
- **验证**：`npm run verify` 通过；用演示服务（`startServer` + 演示 AI，数据放临时目录，接口和 key 都是编造的）在内置浏览器里走过：勾选并保存「也给 Claude Code 用」、新建空间时选「Claude · Kimi」「Pi · DeepSeek」、建好后成员存下 `source`、标签正确；深浅两种配色都截了图。`npm run mock` 能正常启动 Electron 窗口。
- **没验证**：真实的 DeepSeek / Kimi / 智谱（等有 key，第 3、4 条和完成标准里的真实跑通）；HTTP 类型的 MCP；macOS / Linux；没用 electron-builder 真的打包量安装包大小；窄屏没看；没有 Git Bash 的电脑上只用测试注入的方式和 PowerShell 工具本身测过，没在一台真没装 Git 的电脑上跑。
- **还没做**（下一批，等有 key 实测后）：旧的 Gemini API、OpenAI 兼容成员自动换成 pi，去掉文件块协议；Gemini API 接口当 pi 的模型来源；接口的上下文窗口预设。

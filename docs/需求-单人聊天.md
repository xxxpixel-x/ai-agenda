# 需求：单人聊天与「只问某个人」

- 整理：2026-11-19
- 起因：OpenMausBot 的主要用法就是和单个 bot 一对一。Agenda 现在只放一个成员的聊天空间也能用，但用的还是多人讨论那一套规则。只有一个 AI 时不存在「几个 AI 记忆分叉」的问题，可以直接用长会话，比一次性对话快、省额度；再加上记忆库、前情提要和自动交接，长期的单人项目也不用自己写交接文档、开新对话（产品重点第 2 条）。
- 方向：以空间为中心，**单人聊天就是只有一个成员的聊天空间**，当成一种正式的形态做好。不做 OpenMausBot 那种以 bot 为中心的通讯录（同一个 AI 跨空间共享记忆），也不做对其他成员保密的私聊。

## 一、怎么进入

- 新建聊天空间时**只选一个成员，就自动是单人聊天**，不加额外的选项和说明。
- 聊天空间的成员减到只剩一个时，也变成单人聊天。

## 二、和多人聊天空间的区别

| | 多人聊天空间 | 单人聊天 |
| --- | --- | --- |
| 会话 | 每轮一次性（延续会话等用量数据再定，见 [需求-上下文与额度](需求-上下文与额度.md)） | **长会话**：只发上次之后的新消息，到 50% 自动交接 |
| 规则 | 轮流发言、轮次上限、[跳过] / [结束] 标记 | 都不要，你说一句它回一句；提示词里不讲「其他成员」 |
| 记忆库、前情提要 | 有 | 有，同一套（见 [需求-记忆库](需求-记忆库.md)） |
| 侧栏 | 聊天图标 | 显示这个 AI 的头像，一眼看出是和谁单聊 |

- 侧栏头像已做（2026-11-19，随前端规划）：`listItem()` 的成员带 `engine`，侧栏对只有一个成员的聊天空间显示它的头像。规则、长会话和「只问某个人」第二批已做，见文末「实现情况」。

- 长会话只放在 Agenda 自己的地方，不出现在你的 Claude Code 等软件的历史里（要实测能不能做到）；做不到的 AI 照旧用一次性对话。
- 改设定、换型号、改权限时换一个新会话，带上交接说明。

## 三、随时拉人进来

- 单人聊天里加一个成员，就变成多人聊天空间：聊天记录、记忆库都在，切回多人的规则和一次性会话。
- 原来那个成员的长会话写一份交接说明后结束，交接说明里值得全员知道的内容整理进记忆库。

## 四、多人空间里「只问某个人」

- 在群里问一句，只想让某个成员回答，其他人不接话。
- 问完还在同一个空间里：他的回答大家都看得到，记忆库照常整理。
- 入口放在成员标签的菜单里（2026-11-20 定）：点成员头像，选「只问 TA」，输入框上方出现一个可以取消的小标记，发出这一条后自动取消。

## 五、模块与接口（第二批，2026-11-20，已实现，偏差见文末）

这一批做单人聊天的规则、长会话和「只问某个人」。到 50% 自动交接、交接说明等上下文管理（第三批）做好再接；在那之前长会话涨满时交给 Claude Code 等自己的压缩。

| 模块 | 做什么 | 对外接口 |
| --- | --- | --- |
| `src/chat.mjs` | 一个成员时走单人规则：不轮流、不限轮次、不认 [跳过] / [结束]；长会话只发上次之后的新消息；改设定、型号、权限或成员数变了就换新会话（先带最近几轮原文，交接说明等第三批） | `userMessage(text, attachments, { only? })`：`only` 是成员 id，只让他回答，其他人不接话。是否单人只看 `host.members.length` |
| `src/prompts.mjs` | 单人的系统提示不讲「其他成员」和发言规则 | 现有函数加 `solo` 参数 |
| 引擎 meta | 长会话用现有的 `meta.resume`；会话能不能不出现在你自己的 AI 软件历史里，写进 meta（例如 `privateSessions`），做不到的照旧一次性对话 | 调用方只看 meta，不按 AI 的 id 判断 |
| `src/space.mjs`、`src/app-server.mjs`（只动发消息那一处） | 把 `only` 从接口传到聊天 | `POST` 发消息的 body 多 `only` |
| `public/js/chat.js` | 成员标签菜单里加「只问 TA」，输入框上方的标记；消息的时间提示里带上编号（见记忆库第四节） | — |

- 要先实测：Claude Code、Codex、DeepSeek Harness 的长会话能不能放在 Agenda 自己的地方。改引擎模块时先停下来说明，因为模型来源的对话也在改 `claude-code.mjs`。
- 测试（模拟 AI）：一个成员时没有轮次和标记规则、长会话第二轮只发新消息、改设定后换新会话、加成员后切回多人规则、「只问某个人」时其他成员不接话。

## 完成标准

- `npm run verify` 通过，用模拟 AI 测试：一个成员时没有轮次和标记规则、长会话只发新消息、加成员后切回多人规则、「只问某个人」时其他成员不接话。
- Claude Code 用真实账号跑一次单人聊天：第二轮记得第一轮读过的文件；到阈值时自动交接后能接着聊。

## 长会话能不能放在 Agenda 自己的地方（实测，2026-11-20，Windows）

只发编造的短消息，没有读任何凭据文件。

| AI | 结论 | 怎么做到 / 为什么做不到 |
| --- | --- | --- |
| Claude Code 2.1.326 | **能** | 运行时设环境变量 `CLAUDE_CONFIG_DIR=<Agenda 数据目录下的一个文件夹>`，并设 `CLAUDE_SECURESTORAGE_CONFIG_DIR` 为你原来的值（没设过就留空字符串，表示用默认的 `~/.claude`）：会话写到 Agenda 的文件夹里，登录照旧用你原来的。去掉 `--no-session-persistence`，第二轮 `--resume <id>` 记得第一轮的内容（实测：第一轮让它记一个数字，第二轮答对）。`~/.claude/projects` 里没有出现这次的会话。这正是 Claude Agent SDK 自己的 sessionStore 用的做法（从 claude.exe 里读到）。注意：换了配置目录后不读你 `~/.claude/settings.json` 里的设置（`--safe-mode` 本来也关掉了大部分自定义），里面配了 `env`（比如代理、第三方接口）的用户长会话会用不上，需要模型来源那部分确认怎么传；`CLAUDE_CODE_PROJECT_DIR_NAME` 只在宿主模式下生效，不能用。 |
| Codex 0.169 | **不能**，照旧一次性（`--ephemeral`） | 会话文件只能写在 `CODEX_HOME/sessions`，而 `CODEX_HOME` 里也放着登录凭据（`auth.json`，刷新令牌会轮换，不能复制一份）。`CODEX_SQLITE_HOME` 能把索引数据库挪到别处，但会话文件照样写进你的 `sessions`。挪走会话文件再续接：app-server 的 `thread/resume` 带 `path` 报 “stale path”，不带 `path` 报 “no rollout found”。 |
| DeepSeek Harness | **未验证**，照旧（`meta.resume` 本来就续接，会话在 DeepSeek Harness 里看得到） | 会话和登录都在 `$DSH_HOME`（默认 `~/.dsh`）下；改 `DSH_HOME` 会连登录一起换掉。它的文档提到凭据有 “inherited” 来源，也许能单独指定凭据，没有深挖；本机账号余额不足，跑不通一次完整回复。 |

所以：Claude Code 可以在单人聊天里用长会话，但要改 `src/engines/claude-code.mjs`（模型来源的对话也在改它），这一批没有改，交给统筹安排，见下面「留给统筹的引擎改动」。在那之前单人聊天里的 Claude Code 仍是一次性对话（每轮带聊天记录），DeepSeek Harness 照旧续接，Codex、Gemini、API 型照旧一次性。

## 实现情况（第二批，2026-11-20，已完成，未提交）

- **是否单人只看成员数**：`host.members.length === 1`，新建时选一个成员、成员减到一个都自动是单人，没有额外选项。
- **单人规则**（`src/chat.mjs`、`src/prompts.mjs`）：系统提示换成 `chat.systemSolo`（不讲参与者、没有轮流和 [跳过] / [结束]）；每轮输入最后一行是「现在请你回复」；不受「每轮来回上限」限制；回复里的 [跳过] / [结束] 不当标记（`parseMarkers(text, { markers: false })`：顺手去掉，只剩标记时原样显示）；它正在回时你又发了几条，说完后再回一次，覆盖这几条。
- **长会话**：引擎 `meta.resume` 的成员照旧一直续接；单人聊天里注册表 `supportsPrivateSessions(engine)` 为真的成员也续接。续接时只发上次之后的新消息。会话 id、看到第几条（`seen`）、会话签名（`sig`）存在 `memberState[成员]`。签名包括：单人 / 多人、引擎、型号、思考档位、设定、实际权限、是否先问再运行命令；签名变了就换新会话（不用改 `space.update`，型号、档位在讨论中改也能识别）。新开的单人长会话只带最近 3 轮原文（从倒数第 3 条「我」的消息开始，更早的计入「更早的 N 条已省略」）；多人和一次性对话照旧带整段聊天记录窗口。切回一次性对话时删掉旧的会话记录。旧数据没有签名，升级后第一轮会换一次新会话。
- **随时拉人进来**：加成员后签名里的「单人」变了，切回多人规则；只支持 privateSessions 的成员变回一次性对话。交接说明、整理进记忆库是第三批的事，这一批没做。
- **只问某个人**：`userMessage(text, attachments, { only })`，`POST /api/spaces/:id/messages` 的 body 多 `only`（`src/space.mjs`、`src/app-server.mjs` 只动了发消息那一处，附件路径也带上）。只排这一个成员，回答里 @ 了别人也不接；讨论进行中发的，当前这位说完就只轮到他。用户消息上记 `only`，之后其他成员看到这条时前面有「（只问 某某）」；被问的成员输入最后一行说明「只问你，其他成员这次不接话」。单人聊天里 `only` 等于普通发言。不是成员 id 时报「没有这个成员」。
- **界面**（`public/js/chat.js`、`public/style.css`、`public/i18n.js`）：成员菜单里在「让 TA 现在发言」上面加「只问 TA」；点了之后输入框里上方出现「头像 只问 某某 ×」小标记，× 或 Esc 取消，发出这一条后自动取消，换空间不带过去。单人聊天不显示「继续讨论」和「接下来：…」，成员菜单里没有「只问」「让 TA 发言」，输入框提示是「说点什么」。消息时间的鼠标提示：有 `seq` 时带「消息 128」（G 合并后才有），我的消息只问了谁也写在这里，不另加标签。
- **测试**：`test/solo-chat.test.mjs`（8 个，模拟 AI）覆盖一个成员时没有轮次和标记规则、不受上限、长会话第二轮只发新消息、改设定 / 型号 / 档位 / 权限后换新会话且只带最近 3 轮、加成员切回多人、减到一个变单人、只问某个人时其他成员不接话。`npm run verify` 通过（142 个测试）。
- **和第五节接口的偏差**：`prompts.mjs` 的 `turnPrompt` 除了 `solo` 场景用 `reason: 'solo'` 表示，另加了 `reason: 'only'` 和 `recent`（新会话从哪条开始带）；`parseMarkers` 加了 `{ markers }`；新导出 `recentStart(messages, rounds)`。chat 调引擎时多传 `keepSession`（新开的会话要留着），注册表多一个 `supportsPrivateSessions`，这两处要和引擎改动一起接，见下。

### 留给统筹的引擎改动（这一批没改）

1. `src/engines/claude-code.mjs`：`meta.privateSessions: true`；`runTurn` 收到 `keepSession` 或 `sessionId` 时，环境变量加 `CLAUDE_CONFIG_DIR=<sessionHome>`、`CLAUDE_SECURESTORAGE_CONFIG_DIR=<process.env.CLAUDE_SECURESTORAGE_CONFIG_DIR ?? process.env.CLAUDE_CONFIG_DIR ?? ''>`，不加 `--no-session-persistence`，并返回 `result.session_id`（现在只在传了 `sessionId` 时返回）。接续导入对话的成员要继续用你原来的配置目录，不能换。
2. `src/engines/index.mjs`：`supportsPrivateSessions = (id) => !!moduleOf(id)?.meta?.privateSessions`；`options()` 给 Claude Code 带上 `sessionHome`（例如 `<数据目录>/sessions/claude-code`，注册表要知道数据目录）。
3. `src/turn-runner.mjs`：把 `keepSession` 传给 `registry.runTurn`（现在按白名单传，会丢掉）。
4. 演示引擎 `src/engines/mock.mjs` 在单人聊天里第 3 轮起会回 `[跳过]`、第 2 轮带 `[结束]`（按多人规则写的）：单人聊天已经不认标记，第 2 轮的 `[结束]` 会被去掉，第 3 轮会原样显示「[跳过]」。要改演示效果得改 mock.mjs。

### 没验证的地方

- 只在 Windows 上做和验证；Claude Code 的私有会话目录做法在 macOS（钥匙串名字由 `CLAUDE_SECURESTORAGE_CONFIG_DIR` 决定，留空时和原来一样）和 Linux 上没验证。
- 界面是用 Node 起演示模式的本机服务、在内置浏览器里走的（深浅两种配色都看了），没开 Electron 窗口。
- 消息编号的提示要等记忆库那部分（G）给消息加 `seq` 才看得到，这里只按「有就带上」写了。
- 完成标准里「Claude Code 用真实账号跑一次单人聊天、第二轮记得第一轮读过的文件、到阈值自动交接」：引擎改动和自动交接（第三批）都还没接，没做。

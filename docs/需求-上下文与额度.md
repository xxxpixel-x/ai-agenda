# 需求：上下文管理、监视器与额度

- 整理：2026-11-18；更新：2026-11-19，加入上下文管理和自动交接
- 起因：
  - Agenda 里每个成员看到的东西都不一样（任务空间的工作者只看自己的子任务，按主题交接后只看简报，导入的长对话会压成摘要，较早的长回复只留开头和结尾，Claude Code、Codex 自己也会压缩会话），用户常遇到「它怎么不知道 X」却没法查。几个 AI 一起跑又很费额度，现在用完了才报错。额度显示参考了 [Orca](https://github.com/stablyai/orca)。
  - 一个空间要能一直用下去，不靠用户开新空间、写交接文档（见 [需求说明](需求说明.md) 的「产品重点」）。前情提要、自动交接参考了 [OpenMausBot](https://github.com/milind-soni/OpenMausBot) 的上下文压缩和「空闲时压缩」。
- 和它配合的共识层见 [需求-记忆库](需求-记忆库.md)。
- **要先实测**：各 AI 报的用量能读到哪些（上下文长度、缓存命中、账号额度、重置时间）。

## 现在的做法

- 聊天里的 Claude Code、Codex 每一轮都是一次性会话，每轮重新发聊天记录：从最新往前装满 6 万字，超出时起点按 10 条一档往后挪；较早的、超过 8000 字的长回复只留头尾（[prompts.mjs](../src/prompts.mjs)）。挪出去的部分直接丢掉。
- 导入的对话作为固定背景每轮都带，不算进那 6 万字；API 成员另外附带最多 6 万字的文件内容。
- 任务空间的工作者每次也是一次性会话。
- 接续导入对话的 Claude Code、DeepSeek Harness 成员的会话会越来越长。

## 一、先记录用量

- 每一轮记下实际用了多少 token、缓存命中多少，按成员、按空间存。
- 后面每一条优化都拿它做依据；成员标签和上下文面板也用这份数据。

## 二、前情提要

- 聊天记录的起点每往后挪一档，就把挪出去的那部分压成摘要，追加到前情提要里，放在聊天记录前面。只在挪档时变，平时不变，不影响缓存。
- 由记忆库指定的那个成员来写（默认第一个，空间设置里能换），和整理记忆库一起做。
- **在空闲时写**：一轮结束后趁空档写好，不耽误下一轮；还没写好时这一轮先照旧显示「更早的 N 条已省略」。
- 聊天记录里在被省略的位置显示成一个折叠块，你能看也能改，改过的以你的为准，之后新增的内容接在后面。
- 前情提要写过程，记忆库写结论；两者同一个成员同时整理。

## 三、预算跟着模型走

- **按 token 估算**：中文一字算一个，英文四个字母算一个，不引入分词库。
- 常见模型在预设里写好上下文大小，自定义接口可以填。
- 遇到「上下文超长」的报错，自动缩小预算重试一次，并记住这个接口的大小。

## 四、总预算

- 导入的背景、聊天记录、附带的文件、记忆库加起来算一个总预算。
- 超出时：先把较早的导入改成摘要；还不够再缩聊天记录，被缩掉的部分由前情提要补上；附带的文件最后缩。

## 五、自动交接

会话会越来越长的成员，上下文用到一定比例时自动换一个新会话，就像你在 Claude Code 里换一个对话框；你只会看到它的上下文又从低处开始。

- **设置**：全局一项「上下文用到 __% 时自动交接」，默认 **50%**，可以选「不自动交接」。不做到每个成员单独设。
- **适用的成员**：接续导入对话的 Claude Code、DeepSeek Harness、pi 成员，以及以后延续会话的成员；任务空间里正在做子任务的工作者。聊天里一次性发言的成员不需要（靠前情提要和记忆库）。
- **交接说明由旧会话自己写**：它知道得最多。在它说完一轮、你还没回的空档写，缓存还热，又便宜又不耽误下一轮。
- **新会话拿到**：记忆库里和它有关的部分；它自己的交接说明（正在做什么、做到哪、还有什么没收尾）；最近几轮原文。交接说明里值得全员知道的内容，交给记忆库整理进共识层。
- **正在干活的工作者不中途换**：只在说完一轮、或做完一次子任务时换。子任务中途涨满时交给 Claude Code 等自己的压缩；协调者规划时把子任务拆得够小，一个会话做得完（规划提示里加这一条）。
- **痕迹**：聊天里不显示；右侧栏的上下文面板里留一行，例如「12:30 换了新会话」。
- 拿不到用量数字的成员不做自动交接。交接说明写失败时保留旧会话，下次再试。

## 六、任务空间

- **随机标记挪到固定内容之后**：现在每次调用换一个新标记，并且放在输入第一行（[task-prompts.mjs](../src/task-prompts.mjs)），重做、打回时缓存完全用不上。改成目标、计划这些不含消息框的部分在前，标记规则紧跟在第一个消息框之前，防伪造的效果不变。
- **前置任务的报告加长度上限**，超出时只放摘要和编号，原文按需去读。
- 每个成员看到的内容不同，上下文和用量按成员分开算、分开显示。
- **待定**：你针对某个子任务说的话（diff 上的批注、对它提问的回答）是否直接交给负责人、不经过协调者（参考 super-agent 的「直接投递」）。

## 七、动作摘要

- 聊天记录里每个 AI 的发言后面附一行它运行过的命令，最多几条，例如「运行了：npm test」。改了哪些文件现在已经有，不重复。

## 八、延续会话（先量再定）

- 一次性会话的好处：每个 AI 看到什么由 Agenda 说了算、各种 AI 一视同仁、设置随时生效、不弄乱你的 AI 软件历史、没有状态不会坏。代价：每轮重新读文件、重新了解项目，忘掉上一轮读过的代码和测试结果。
- 有了记忆库（防止各成员记忆分叉）和自动交接（防止会话无限变大），可以考虑折中做法：讨论进行中保持会话、只发新消息；停了一段时间（比如 10 分钟）、改了设定 / 权限 / 成员、上一轮出错或被打断、到了自动交接的比例时，换回全新会话。长会话只放在 Agenda 自己的地方，不出现在你的 Claude Code 历史里（要实测能不能做到）。
- 等第一条的用量数据出来，对比两种做法差多少再决定。

## 九、成员标签

- 一个小圈：上下文用了多少，快满时变色；自动交接后降回低处。
- 额度快用完时标签变色提醒，平时不显示。
- 鼠标停上去一次显示「上下文 X%、额度 Y%，几点重置」。
- 一次性发言的成员不显示百分比，显示「最近 N 条在、更早的 M 条已压进前情提要」。

## 十、右侧栏「上下文」面板

- 选一个成员，列出它这次看到的内容和大概各占多少：
  - 角色说明 / 设定
  - 记忆库（带了哪几条）
  - 前情提要、简报、导入摘要
  - 最近 N 条聊天
  - 被省略的部分（省略了多少条、多少字）
- 自动交接的记录。
- 一个按钮「重开这个 AI 的会话」，重开时带上交接说明。正在发言时不能点。

## 十一、各 AI 显示什么

| AI | 上下文 | 额度 |
| --- | --- | --- |
| Claude Code | 读它输出里的用量；会话型成员直接问它自己（`get_context_usage`，2.1.325 起支持，不调用模型、不花额度，要实测） | 能读到就显示「已用 X%，几点重置」 |
| Codex | 读它输出里的用量 | 同上 |
| pi 成员、Claude Code 配别家模型（见 [需求-模型来源](需求-模型来源.md)） | 读 pi / Claude Code 报的用量 | 没有额度的说法，**只显示 token 数**（这个空间、今天各用了多少），不算钱，不显示接口余额 |
| 其他 | 拿不到准确数字时，只列出 Agenda 发了哪些内容，不显示百分比 | 不显示 |

## 完成标准

- `npm run verify` 通过，用模拟 AI 测试：面板里的内容拆分、前情提要的挪档和固定前缀、预算估算和超长重试、总预算的缩减顺序、自动交接的触发和交接内容、任务提示里标记的位置。
- Claude Code 和 Codex 用真实账号核对用量数字和各自显示的一致；用真实 AI 跑一次自动交接，新会话能接着做。

# 需求：空间记忆库

- 整理：2026-11-19；更新：2026-11-20，和 Codex 讨论后加入决定的来源和原因、「否决过」、取代用追加的更正、按任务依赖取材料
- 起因：一个空间要能一直用下去（见 [需求说明](需求说明.md) 的「产品重点」），几个 AI 来自不同厂家、每轮可能都是新会话，需要一份所有成员共用的「现在什么是对的」。参考了 [DeepSeek super-agent](https://github.com/deepseek-ai/dsh-superagent-prototype) 的「上下文当缓存」「顺着编号回忆」，[OpenMausBot](https://github.com/milind-soni/OpenMausBot) 的记忆和群聊记忆规则；Obsidian 的双向链接只作为启发。
- 定位：聊天记录是过程，记忆库是结论，是这个空间的**共识层**。
- **为 AI 设计，不为人浏览**：格式、粒度、加载方式都按 AI 好理解、好检索来定。给人看的展示前端（「记忆库」按钮，做得好看一些）放到以后，只读出来展示，不反过来影响存储格式。
- 和它配合的上下文管理（前情提要、预算、自动交接）见 [需求-上下文与额度](需求-上下文与额度.md)。

## 一、条目

一条只说一件事，单独拿出来也看得懂。

| 类型 | 例子 |
| --- | --- |
| 决定 | 登录用短信验证码 |
| 约束 | 不能引入新的依赖 |
| 项目事实 | 前端用的是 Vue 3 |
| 你的偏好 | 回复用中文；文档不要加多余的说明 |
| 未解决的问题 / 提议 | 要不要支持第三方登录（Alice 提议，还没定）；代码现在用邮箱登录，和 #12 不一致（分歧） |
| 否决过 | 登录不用邮箱：目标用户多数没有邮箱（讨论时否决）；某个库在 Windows 上跑不起来（T2 试过） |
| 任务结果 | T3 登录页做完，改了 `src/login.js` |

每条记下：

- **编号**：空间内递增，不复用，例如 `#12`。编号就是版本：同一件事有了新说法就是一条新条目，旧的标成被取代，不另加版本号；
- **类型、内容**（短，一两句）；
- **原因**：决定、约束、否决过要写，一句话说为什么。之后判断新说法能不能取代它，就看有没有回应这个原因；
- **来源**：决定才有，「你定的」或「默认通过的」（见第二节）；
- **状态**：有效 / 已被 #N 取代 / 已解决；
- **出处**：来自哪几条消息、哪个任务（哪次执行）、哪个文件，**必填**；
- **相关条目**：编号列表，例如这条决定落实在哪个任务结果里；
- **涉及的文件和主题**：用来按成员挑选；
- **日期**：原消息的时间；补导的旧对话另记导入时间。

## 二、写入规则

- **出处必填**：没有出处的不收，免得 AI 凭空「记住」不存在的事。
- **分清是谁说的**：
  - 你说的、你同意过的，记成决定（或约束、偏好），来源是「你定的」；
  - AI 提出、没人反对、并且已经照着做了的，也算决定（宽松，让你少做决定），来源是「默认通过的」，出处要指向实际照做的任务或改动；
  - 其余 AI 的建议记成「提议」，AI 没验证过的说法不算项目事实。
- **什么能取代旧条目**：同一件事、适用范围相同，并且回应了旧条目的原因，才算取代。旧条目标成「已被 #N 取代」。先后按原消息的时间算，补导的旧对话不会因为导入得晚就盖过后来的决定。
  - 「默认通过的」决定：另一个 AI 按同样的宽松规则就能改；
  - 「你定的」决定：只有你能改。AI 的做法和它不一样时，这条决定不动，另记一条项目事实（代码现在什么样）和一条分歧，整理者问你一句；
  - 分不清时也问你一句。
- **否决过**：你否掉的提议、成员实际试过走不通的做法，都记成「否决过」，写上原因，出处写明来自哪段讨论或哪个任务的哪次执行。免得别的成员换个说法再提一遍、再踩一遍。
- **任务打回重做**：新的结果记成新条目，取代旧的；旧的留着追溯。
- **谁写、什么时候写**：你在空间设置里指定的那个成员（默认第一个，可以挑便宜的），在空闲时把新的聊天、任务结果整理进来。它同时写前情提要。其他成员想记什么，在发言里说「这条记一下」，由它整理进去；其他成员不直接改记忆库。

## 三、怎么给 AI

- **只给有效的**：被取代、已解决的条目默认不加载，需要时 AI 自己去查。
- **分层加载**：
  1. 每轮都带：有效的决定、约束、你的偏好、否决过（短）；
  2. 只带目录：主题、任务，每个一行；
  3. 需要时再读：详细内容、条目的来龙去脉、聊天原话。
  超出这个成员的预算时，第 1 层也按相关程度挑。
- **按成员取**：真相只有一份，每人拿自己需要的部分。
  - 群聊：按当前话题挑。
  - 任务空间：协调者拿全局。工作者按这个顺序：全员都要遵守的约束、偏好和否决过 → 自己的子任务 → 直接依赖的前置任务最新验收通过的结果 → 按涉及的文件、主题补充。例如 T1 第一版接口被打回、第二版通过，依赖它的 T3 默认拿第二版，第一版能顺着编号查到为什么被否。
- **自动检索**：每轮发言前，Agenda 拿最新的消息去记忆库里搜相关条目，附在这一轮的输入里（放在消息里，不放系统提示，免得系统提示每轮都变）。没想到去查、或者没有读文件工具的成员也用得上。
- **顺着编号回忆**：给出的每条都带出处和相关条目的编号，AI 想深入就顺着编号去读。
- **固定格式和顺序**：按编号排列、只追加，每轮输入的前面部分不变，能命中缓存。
- **取代用追加的更正**：条目被取代时，已经发出去的内容不改，在后面追加一行，例如「#20 取代 #12：登录改回短信」。第 1 层只在前情提要挪档时重新整理一次，那时才去掉被取代的条目。这样缓存不受影响；延续会话的成员历史里还留着旧条目，也能从更正知道它作废了。

## 四、存储

- 源数据存成一行一条的结构化记录；给 AI 的是渲染好的文字，每条一行，例如：
  `#12 [决定·你定的] 登录用短信验证码——目标用户多数没有邮箱（出处：消息 128、任务 T3；相关：#7、#15）`
- 同时渲染一份文件给有读文件工具的 AI 按需查阅，聊天原话也按编号存成文件。
- **待定**：放在共享文件夹的隐藏目录（AI 用自己的工具就能读，Git 项目里自动排除），还是 Agenda 的数据目录。

## 五、展示前端（以后做）

- **是什么**：一个「记忆库」按钮，点开是这个空间记忆库的展示页，做得好看、吸引人，可以用上粒子效果（见 [需求-前端规划](需求-前端规划.md) 第七节）。
- **为什么值得做**：让你一眼看到「AI 现在记住了什么」，出了问题时方便查，有助于建立信任；也是产品的一个亮点。
- **只读出来展示**：记忆库本身还是按 AI 好理解的方式存，展示页只负责读出来，不反过来影响存储格式。
- **什么时候做**：等记忆库本身跑通了再做，不然展示的是空架子。
- **待定**：按钮放在哪（侧栏、资源库里，还是右侧栏的一个面板）；能不能在展示页里改或删条目。

## 完成标准

- `npm run verify` 通过，用模拟 AI 测试：写入规则（出处、来源、取代、否决过、补导旧对话按原时间）、分层加载、按成员挑选（含任务依赖和打回重做）、自动检索、追加更正和挪档时重整、格式稳定。
- 用真实 AI 从一段原始中文群聊开始跑，不直接往记忆库里塞条目：你先定 A，一个 AI 提议 B，你确认 C，再补导一段还在讨论 A 的旧对话，然后交接给另一个成员接着干活。检查它收到的当前决定是 C、能说出是谁定的 C、做出的改动遵循 C；A 和 B 不再被当成当前决定，B 不被重新提起。出错时按上下文面板记下的条目编号，分清是整理时记错、检索时取错，还是收到了没照做。

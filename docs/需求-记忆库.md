# 需求：空间记忆库

- 整理：2026-11-19
- 起因：一个空间要能一直用下去（见 [需求说明](需求说明.md) 的「产品重点」），几个 AI 来自不同厂家、每轮可能都是新会话，需要一份所有成员共用的「现在什么是对的」。参考了 [DeepSeek super-agent](https://github.com/deepseek-ai/dsh-superagent-prototype) 的「上下文当缓存」「顺着编号回忆」，[OpenMausBot](https://github.com/milind-soni/OpenMausBot) 的记忆和群聊记忆规则；Obsidian 的双向链接只作为启发。
- 定位：聊天记录是过程，记忆库是结论，是这个空间的**共识层**。
- **为 AI 设计，不为人浏览**：格式、粒度、加载方式都按 AI 好理解、好检索来定。给人看的展示前端（「记忆库」按钮，做得好看一些）放到以后，只读出来展示，不反过来影响存储格式。
- 和它配合的上下文管理（前情提要、预算、自动交接）见 [需求-上下文与额度](需求-上下文与额度.md)。

## 一、条目

一条只说一件事，单独拿出来也看得懂。

| 类型 | 例子 |
| --- | --- |
| 决定 | 登录用短信验证码 |
| 约束 | 不能引入新的依赖 |
| 项目事实 | 前端用的是 Vue 3 |
| 你的偏好 | 回复用中文；文档不要加多余的说明 |
| 未解决的问题 / 提议 | 要不要支持第三方登录（Alice 提议，还没定） |
| 任务结果 | T3 登录页做完，改了 `src/login.js` |

每条记下：

- **编号**：空间内递增，不复用，例如 `#12`；
- **类型、内容**（短，一两句）；
- **状态**：有效 / 已被 #N 取代 / 已解决；
- **出处**：来自哪几条消息、哪个任务、哪个文件，**必填**；
- **相关条目**：编号列表，例如这条决定落实在哪个任务结果里；
- **涉及的文件和主题**：用来按成员挑选；
- **日期**。

## 二、写入规则

- **出处必填**：没有出处的不收，免得 AI 凭空「记住」不存在的事。
- **分清是谁说的**：
  - 你说的、你同意过的，记成决定（或约束、偏好）；
  - AI 提出、没人反对、并且已经照着做了的，也算决定（宽松，让你少做决定）；
  - 其余 AI 的建议记成「提议」，AI 没验证过的说法不算项目事实。
- **新旧矛盾时以新的为准**：旧条目标成「已被 #N 取代」，默认不再加载；分不清时才问你一句。
- **谁写、什么时候写**：你在空间设置里指定的那个成员（默认第一个，可以挑便宜的），在空闲时把新的聊天、任务结果整理进来。它同时写前情提要。其他成员想记什么，在发言里说「这条记一下」，由它整理进去；其他成员不直接改记忆库。

## 三、怎么给 AI

- **只给有效的**：被取代、已解决的条目默认不加载，需要时 AI 自己去查。
- **分层加载**：
  1. 每轮都带：有效的决定、约束、你的偏好（短）；
  2. 只带目录：主题、任务，每个一行；
  3. 需要时再读：详细内容、条目的来龙去脉、聊天原话。
  超出这个成员的预算时，第 1 层也按相关程度挑。
- **按成员取**：真相只有一份，每人拿自己需要的部分。任务空间的协调者拿全局；工作者拿和自己子任务相关的（按涉及的文件、主题匹配），加上全员都要遵守的约束和偏好。
- **自动检索**：每轮发言前，Agenda 拿最新的消息去记忆库里搜相关条目，附在这一轮的输入里（放在消息里，不放系统提示，免得系统提示每轮都变）。没想到去查、或者没有读文件工具的成员也用得上。
- **顺着编号回忆**：给出的每条都带出处和相关条目的编号，AI 想深入就顺着编号去读。
- **固定格式和顺序**：按编号排列、只追加，每轮输入的前面部分不变，能命中缓存。

## 四、存储

- 源数据存成一行一条的结构化记录；给 AI 的是渲染好的文字，每条一行，例如：
  `#12 [决定] 登录用短信验证码（出处：消息 128、任务 T3；相关：#7、#15）`
- 同时渲染一份文件给有读文件工具的 AI 按需查阅，聊天原话也按编号存成文件。
- **待定**：放在共享文件夹的隐藏目录（AI 用自己的工具就能读，Git 项目里自动排除），还是 Agenda 的数据目录。

## 五、展示前端（以后做）

- **是什么**：一个「记忆库」按钮，点开是这个空间记忆库的展示页，做得好看、吸引人，可以用上粒子效果（见 [需求-前端规划](需求-前端规划.md) 第七节）。
- **为什么值得做**：让你一眼看到「AI 现在记住了什么」，出了问题时方便查，有助于建立信任；也是产品的一个亮点。
- **只读出来展示**：记忆库本身还是按 AI 好理解的方式存，展示页只负责读出来，不反过来影响存储格式。
- **什么时候做**：等记忆库本身跑通了再做，不然展示的是空架子。
- **待定**：按钮放在哪（侧栏、资源库里，还是右侧栏的一个面板）；能不能在展示页里改或删条目。

## 完成标准

- `npm run verify` 通过，用模拟 AI 测试：写入规则（出处、谁说的、取代）、分层加载、按成员挑选、自动检索、格式稳定。
- 用真实 AI 跑一段长讨论：早期的决定在聊天记录被省略之后仍然被遵守，被推翻的决定不再出现。

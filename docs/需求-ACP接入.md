# 需求：自定义 AI（ACP 接入）

- 整理：2026-11-18
- 起因：Agenda 要兼容很多 AI 软件，现在每种 AI 都要单独写一个引擎。不少命令行 AI 已经支持 ACP（Agent Client Protocol），做一个通用接入，以后新的 AI 填配置就能加。参考了 [OpenMausBot](https://github.com/milind-soni/OpenMausBot) 的自定义引擎。
- 已经接好的 Claude Code、Codex、Gemini CLI、DeepSeek Harness 保持原样，不改成 ACP。
- API 模型改走内嵌的 pi（见 [需求-模型来源](需求-模型来源.md)），不需要 ACP。ACP 只给想接其他命令行 AI 的用户。

## 一、怎么加

- 全局设置的「AI 连接」里点「自定义 AI」，填：名字、启动命令和参数、（可选）图标颜色。
- 保存后 Agenda 启动它试一次 ACP 握手，成功了才显示「可用」，失败显示原因。
- 加好以后和其他 AI 一样，能加进空间当成员、能选型号（AI 提供的话）。

## 二、权限

Agenda 管不住自定义 AI 自己做什么，「只读」「可改文件」两档没法保证。

- ACP 里 AI 想改文件、运行命令时会先发请求，接到现有的审批卡片上。
- 「只读」「可改文件」两档：每一次改文件、运行命令都弹卡片问你。
- 「可运行命令」档：运行命令弹卡片，改文件不问（和现在的规则一样）。
- 「全部权限」：都不问。
- 不按协议发请求、直接动手的 AI，成员标签上标「这个 AI 的权限无法保证」。

## 要先实测

- 挑两三个支持 ACP 的命令行 AI 试接，确认握手、发消息、流式输出、权限请求都能用。
- ACP 的权限请求能不能覆盖改文件和运行命令两种，还是只有运行命令。

## 完成标准

- `npm run verify` 通过，用一个模拟的 ACP 程序测试握手、发言、审批。
- 至少一个真实的 ACP AI 跑通聊天空间和任务空间。
